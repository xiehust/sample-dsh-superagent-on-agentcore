# E2E setup checklist (A2): GitHub App + Feishu/Lark bot

Follow this once, after `scripts/deploy.sh` has deployed every `dshsa-*` stack in ap-northeast-1. It ends with the `dshsa-admin` commands that register the App and the bot, after which A2 can run end to end: mention → acknowledgement → PR → ready reply, both from GitHub and from a bound Feishu chat.

Commands run from the repository root with the platform admin's AWS credentials for the account in `DSHSA_ACCOUNT`. `dshsa-admin` is run as `pnpm --filter @dshsa/control-api admin <command>`, abbreviated `admin` below:

```sh
export AWS_REGION=ap-northeast-1
alias admin='pnpm --silent --filter @dshsa/control-api admin'
```

Keep secrets (the App private key, the Feishu App Secret) out of chat, tickets and this repository.

## 0. Collect the deployment outputs

The command blocks in this guide contain no `#` comments, so they paste safely into zsh, where interactive comments are off by default.

Show the stack outputs and check the ingress. `check:ingress` must print ✓ on every line before you continue:

```sh
aws cloudformation describe-stacks --stack-name dshsa-ingress --query "Stacks[0].Outputs" --output table
pnpm --filter @dshsa/sources check:ingress
```

- **Webhook URL**: output `GithubWebhookUrl` (deployed 2026-11-01; `check:ingress` passed all 5 checks against it). Re-read the output if the stack is ever destroyed and redeployed, because the API id changes.
- **Webhook secret**: the `webhookSecret` in `dshsa/github-app`, generated by `dshsa-shared`. **It is sensitive**: anyone holding it can sign webhook deliveries that the ingress accepts. Don't print it, and paste it nowhere except the App's **Webhook secret** field in step 1. Copy it straight to the clipboard right before that step, without showing it.

  On macOS:

  ```sh
  aws secretsmanager get-secret-value --secret-id dshsa/github-app --query SecretString --output text | jq -r .webhookSecret | tr -d '\n' | pbcopy
  ```

  On a Linux desktop, replace `pbcopy` with `wl-copy` (Wayland) or `xclip -selection clipboard` (X11). In a shell on a remote host over SSH, such as a dev desktop, send it to your local clipboard with an OSC 52 escape sequence instead. The terminal consumes the sequence and doesn't display it. Your terminal must allow clipboard access (iTerm2: *Applications in terminal may access clipboard*; inside tmux: `set -g set-clipboard on`):

  ```sh
  printf '\033]52;c;%s\a' "$(aws secretsmanager get-secret-value --secret-id dshsa/github-app --query SecretString --output text | jq -r .webhookSecret | tr -d '\n' | base64 | tr -d '\n')"
  ```

  After pasting it into the App, copy something else to clear the clipboard.

## 1. Create the GitHub App

GitHub → **Settings → Developer settings → GitHub Apps → New GitHub App** (or under the organization that owns the test repositories: **Organization settings → Developer settings → GitHub Apps**).

- [ ] **GitHub App name**: a short name, for example `dshsa-e2e-agent`. Its **slug** (shown on the App page after creation) is what people mention: `@dshsa-e2e-agent`.
- [ ] **Homepage URL**: any URL, for example the `dshsa-panel` output `PanelUrl`.
- [ ] **Identifying and authorizing users**: click **Add redirect URI** and enter the **Redirect URI** (formerly Callback URL) `<PanelUrl>/setup/github/callback`. Leave **Allow wildcard matching**, **Request user authorization (OAuth) during installation** and **Enable Device Flow** unchecked.
- [ ] **Post installation → Setup URL** (optional): `<PanelUrl>/setup/github`, and turn on **Redirect on update**.

  `<PanelUrl>` is the `dshsa-panel` output `PanelUrl`. The panel's **Platform → GitHub App** checklist shows both URLs with copy buttons, so you can also fill them in later from there. They are needed only for linking installations in the panel; the CLI flow in step 3 works without them.
- [ ] **Webhook → Active**: on.
- [ ] **Webhook URL**: `https://<api-id>.execute-api.ap-northeast-1.amazonaws.com/github/webhook` (the `GithubWebhookUrl` from step 0).
- [ ] **Webhook secret**: paste the `webhookSecret` you copied to the clipboard in step 0.
- [ ] **SSL verification**: enabled.
- [ ] **Repository permissions**:

  | Permission | Access |
  |---|---|
  | Actions | Read-only |
  | Checks | Read-only |
  | Commit statuses | Read-only |
  | Contents | Read and write |
  | Issues | Read and write |
  | Metadata | Read-only (mandatory) |
  | Pull requests | Read and write |

  **Organization permissions → Members**: Read-only. The panel uses it to check that whoever links an organization's installation is an admin of that organization. Every other repository, organization and account permission: **No access**.
- [ ] **Subscribe to events**: `Check suite`, `Issue comment`, `Issues`, `Pull request`, `Pull request review`, `Pull request review comment`, `Status`, `Workflow run`.
- [ ] **Where can this GitHub App be installed?**: "Only on this account", or "Any account" if a test tenant lives in another org.
- [ ] **Create GitHub App**, then note the **App ID** (numeric) and the **slug**.
- [ ] **Private keys → Generate a private key**: save the `.pem` outside the repository, for example `~/dshsa-e2e-agent.private-key.pem`.
- [ ] **Install App → Only select repositories**: pick the test repository (A1). Note the **installation id**, the number at the end of the installation page URL (`https://github.com/settings/installations/<id>`, or `…/organizations/<org>/settings/installations/<id>`).
- [ ] Note the repository's numeric id: `gh api repos/<owner>/<repo> --jq .id`.
- [ ] Advanced → **Recent Deliveries** shows the `ping` with **200**. This works before step 3, because `dshsa-shared` already generated the webhook secret. A **401 bad_signature** means the App's webhook secret differs from `webhookSecret`. Copy it again (step 0), paste it, and **Redeliver**.

## 2. Create the Feishu / Lark self-built bot

Open the developer console of the platform the test chat lives on: Feishu https://open.feishu.cn/app or Lark https://open.larksuite.com/app. The choice is the tenant's `--domain` (`feishu` or `lark`) in step 3.5.

- [ ] **Create custom app** (创建企业自建应用): any name, for example `dshsa e2e agent`.
- [ ] **Add features → Bot** (添加应用能力 → 机器人).
- [ ] **Permissions & scopes** (权限管理). Grant these tenant-token scopes, search by the console name:
  - [ ] Receive group chat messages that @ the bot (接收群聊中@机器人消息事件)
  - [ ] Read direct messages sent to the bot (读取用户发给机器人的单聊消息)
  - [ ] Obtain and send messages in direct and group chats (获取与发送单聊、群组消息)
  - [ ] Obtain group information (获取群组信息)
  - [ ] Obtain group members (获取群成员信息)
  - [ ] Read and upload images or files (获取与上传图片或文件资源)
  - [ ] Optional: Read all messages in groups (获取群组中所有消息), only for a chat set to **All** instead of **@ only**
- [ ] **Credentials & basic info** (凭证与基础信息): note the **App ID** (`cli_…`) and **App Secret**. If you set an **Encrypt Key** under Events & callbacks, note it too.
- [ ] Run the `admin feishu set` command of step 3.5 **before** the next item. The console only saves long-connection mode while a client is connected, and the host's Connector connects within about a minute of the secret being set. Check `/dshsa/host` in CloudWatch Logs for `feishu.health` … `Listening for bot events`.
- [ ] **Events & callbacks → Event configuration** (事件与回调 → 事件配置): subscription mode **Receive events through persistent connection** (使用长连接接收事件), then save. Add the event **Message received** `im.message.receive_v1` (接收消息).
- [ ] **Version management & release** (版本管理与发布): create a version and publish it. Have the tenant admin approve it in the admin console if asked.
- [ ] Add the bot to the test chat (chat settings → **Bots → Add bot**).
- [ ] Send one message mentioning the bot in that chat. The Connector records the unbound chat and logs `feishu.unrouted` with its `chatId` (`oc_…`) in `/dshsa/host`. Note the chat id for step 3.6. To find it in the log, use CloudWatch Logs Insights on `/dshsa/host` with `filter @message like /feishu.unrouted/`.

## 3. Register everything with `dshsa-admin`

Replace the `<…>` values. Run the commands in this order, because a panel user and a cell need their tenant, and a chat binding needs its cell.

1. The tenant (once): the team that owns the test repository.

   ```sh
   admin tenant add e2ea --name "E2E tenant A"
   ```

2. A panel user for the tenant, created right after it so you can sign in to the panel at any later point (the Policy, the chat bindings, the ticket). Cognito emails a temporary password, and the first sign-in asks for a new one. If no email arrives, pass `--temp-password '<Temp-Passw0rd!>'` and sign in with that.

   ```sh
   admin user add <you@example.com> --tenant e2ea
   ```

3. The GitHub App identity (platform-wide, once). It keeps the `webhookSecret` that is already set. It checks the key and App ID with GitHub (`GET /app`) and stores the App's real slug. The slug is the last part of the App page URL (`github.com/apps/<slug>`), **not** the Client ID (`Iv…`); `--slug` is optional, and a wrong one is refused. Cells read the slug at start, so if the host is already running, restart it afterwards.

   ```sh
   admin github app-set --app-id <APP_ID> --private-key-file ~/dshsa-e2e-agent.private-key.pem
   ```

4. The installed repository becomes a cell. This prints the cellId (`e2ea--gh<repoId>`) and creates the cell's queue and route.

   ```sh
   admin cell add e2ea --repo <owner>/<repo> --repo-id <REPO_ID> --installation-id <INSTALLATION_ID> --default-branch main
   ```

   Only if the App was installed again later (a new installation id), point the tenant's cells at the new installation:

   ```sh
   admin github-install register e2ea <INSTALLATION_ID>
   ```

5. The Feishu/Lark bot secret for the tenant. `read -rs` waits for you to paste the App Secret and doesn't echo it, so it stays off the screen and out of shell history. Press Enter after pasting. For a Lark tenant use `--domain lark`. If you set an Encrypt Key, add `--encrypt-key <Encrypt Key>`.

   ```sh
   read -rs FEISHU_APP_SECRET && echo
   admin feishu set e2ea --domain feishu --app-id <cli_APP_ID> --app-secret "$FEISHU_APP_SECRET"
   unset FEISHU_APP_SECRET
   ```

6. Bind the test chat to the cell. The host adds it to the cell's Feishu Chats as **@ only** within about 60 s.

   ```sh
   admin chat bind e2ea <oc_CHAT_ID> e2ea--gh<REPO_ID> --name "<chat name>"
   ```

7. Check the tenant's cells.

   ```sh
   admin cell list --tenant e2ea
   ```

### Set the Policy in the panel

Open the panel (`dshsa-panel` output `PanelUrl`) and sign in as the step 3.2 user. Pick the cell `e2ea--gh<REPO_ID>`, then open **Settings → Configuration → Policy**.

The Policy is a raw JSON editor over `{ "rules": [...], "sources": {...} }`. The editor checks only the JSON syntax; the host validates the block when you press **Save** and answers a mistake with an error. If someone else saved in the meantime, the save is refused: reload and edit again.

- [ ] Leave `rules` as it is.
- [ ] Under `sources`, list the people who may originate work:

  ```json
  "sources": {
    "github": { "allowed": [{ "id": "<your-github-login>" }] },
    "feishu": { "allowed": [{ "id": "ou_<your open_id>", "name": "<your name>" }] }
  }
  ```

  - **GitHub** entries are `{ "id": "<login>" }` only: no other keys, and the login without `@`.
  - **Feishu** entries are `{ "id": "ou_…", "name": "…" }`, and `name` is optional. The id is your **open_id** for this bot: open_ids differ per app, so a user ID or an open_id from another app won't match.
  - A `syncChat` key may appear under `feishu`. Leave it as `""`: this panel has no **Sync now** button, so nothing reads it.
- [ ] **Save**.
- [ ] **Settings → Feishu chat bindings** lists the bound test chat.

To find your **open_id**, list the test chat's members through the bot. This uses the bot's **Obtain group members** scope from step 2. It reads the App credentials from `dshsa/feishu/e2ea` into a short-lived tenant token without printing either. Replace `<oc_CHAT_ID>`, and on Lark use `https://open.larksuite.com` in both URLs:

```sh
FEISHU_TOKEN="$(aws secretsmanager get-secret-value --secret-id dshsa/feishu/e2ea --query SecretString --output text | jq '{app_id: .appId, app_secret: .appSecret}' | curl -s -X POST https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal -H 'content-type: application/json' -d @- | jq -r .tenant_access_token)"
curl -s -H "authorization: Bearer $FEISHU_TOKEN" "https://open.feishu.cn/open-apis/im/v1/chats/<oc_CHAT_ID>/members?member_id_type=open_id&page_size=100" | jq -c '.data.items[] | {id: .member_id, name}'
unset FEISHU_TOKEN
```

Each output line is already an entry for `feishu.allowed`. If you have no AWS access, ask the platform admin to run it for you.

By default the **Eval** block has `"mode": "observe"`. That only affects messages that don't @-mention the agent, and an @-mention from an allowed person is evaluated in every mode, so A2 needs no change there.

## 4. Run A2

- [ ] **GitHub**: in the test repository, open an Issue and comment `@<app-slug> add a CONTRIBUTING.md with a short how-to-build section`. Expect, in order: a webhook delivery with **202** in **Recent Deliveries**, an acknowledgement comment by `<app-slug>[bot]`, a PR from an `agent/<name>` branch by `<app-slug>[bot]`, then a ready reply in the Issue. The panel's Overview shows the ticket.
- [ ] **Feishu**: in the bound chat, send `@<bot name> add a short FAQ section to README.md`. Expect a threaded acknowledgement from the bot, a PR in the bound repository, then a ready reply in the same thread.
- [ ] Automated checks: `scripts/e2e/run.sh` (A5, A6 and the ingress checks) must print `all steps passed`.

## Troubleshooting

| Symptom | Where to look / fix |
|---|---|
| Recent Deliveries shows 401 | The App's webhook secret differs from `dshsa/github-app` `webhookSecret`. Paste it again |
| Recent Deliveries shows 503 | The Lambda cannot read a usable `webhookSecret` (missing, or shorter than 20 characters) from `dshsa/github-app`: run `admin github app-set … --webhook-secret <s>` and paste the same value into the App |
| 202 but `{"ignored":"unrouted"}` | No cell for this installation and repository. Check `admin cell list` and the installation id (`github-install register`) |
| Delivery 202 but no acknowledgement | Your login is not on the GitHub allowed list, or the comment doesn't mention `@<app-slug>` (an edited Issue body does not count; post a comment). Check `/dshsa/host` |
| Feishu console refuses to save long-connection mode | The Connector isn't connected yet: run `admin feishu set` first and wait for `Listening for bot events` in `/dshsa/host` |
| Feishu mention gets no reply | The chat isn't bound (`feishu.unrouted` in `/dshsa/host`), the bot isn't in the chat, or your `open_id` isn't on the Feishu allowed list |
